# AresOS — Дорожная карта

**Цель проекта:** 64-битная ОС «голого железа» (x86-64) на C + ассемблере (GAS) с собственным
UEFI-загрузчиком, которая в финале запускает Windows-приложения формата PE (.exe)
через собственный слой совместимости WinAPI (подход, как у Wine/ReactOS, но «снизу»).

**Честная оценка:** полноценный запуск любых Windows-программ — это уровень Wine
(30+ лет разработки командой). Наш реалистичный ориентир: сначала **консольные
.exe** (hello world, скомпилированный MinGW), затем последовательное расширение
API. Каждый этап ниже — рабочая, проверяемая версия ОС.

## M4. Прерывания и время ✅ СДЕЛАНО (v0.4.0)

- ACPI: RSDP берём из EFI ConfigurationTable (GUID ACPI 2.0/1.0; legacy-скан
  0xE0000 как запасной путь), разбор XSDT/RSDT → MADT → LAPIC/IOAPIC адреса,
  BSP APIC ID, GSI-overrides. `kernel/drivers/acpi.c`.
- LAPIC-таймер 100 Гц: калибровка по PIT каналу 2 (one-shot ~50 мс),
  periodic-режим, вектор 0x40. `kernel/drivers/lapic.c`.
- IOAPIC: клавиатура (IRQ1→vec 33) и мышь (IRQ12→vec 44) маршрутизируются
  на BSP; старая модель «PIC 8259 + PIT ch0 100 Гц» оставлена как автоматический
  fallback, если ACPI/MADT нет или калибровка не сошлась.
- Клавиатура PS/2: IRQ-обработчик, scancode set 1 → ASCII (Shift/CapsLock),
  F1..F10, стрелки (E0-префикс), кольцевой буфер на 64 события. `kernel/drivers/keyboard.c`.
- Отложено: MSI, x2APIC, HPET/TSC-калибровка, `rdtsc`-профилирование.

**DoD выполнен:** ядро реагирует на клавиши (последняя клавиша рисуется в док),
аптайм по системному тику 100 Гц обновляется каждую секунду.

## M5. Многозадачность ✅ СДЕЛАНО (v0.4.0)

- Ядровые потоки (ring-0): у каждого свой стек 16 КиБ (kmalloc),
  старт — через фейковый IRQ-кадр + `iretq` в `proc_trampoline`. `kernel/proc.c`.
- Планировщик round-robin: переключение ТОЛЬКО из тика таймера — подмена
  указателя стека перед `pop/iretq` в `irq_common` (все кадры одной формы).
  Квант 4 тика (40 мс), вытеснение, сон по `proc_sleep(ms)` с пробуждением
  по wake_tick, лимит 32 процесса.
- Потоки: `idle` (kmain), `desktop` (обычный), фоновые демоны `heartbeat`
  (мигает огоньком в доке) и `sysmon` (пульс в serial).
- **Диспетчер задач на десктопе (F2)**: таблица id/имя/состояние/тики CPU/тип
  (normal/background), обновление 4 раза в секунду, подсветка текущего потока.
- Проверено host-симуляцией логики планировщика (честный RR, квант, сон/будка,
  лимит) — тот же приём, что поймал 2 бага кучи в v0.3.2.
- Отложено (M5.1+): приоритеты, spinlock/mutex, SMP, FXSAVE (мы пока без FPU-
  контекста, `-mgeneral-regs-only`), user-mode задачи и TSS.

**DoD выполнен:** heartbeat (фон) и desktop (обычный) крутятся параллельно —
огонёк мигает, мышь/окна отзываются, диспетчер показывает живые счётчики тиков.

## M6. Диск и файловая система
_3–5 недель_

- Драйвер диска: AHCI (SATA) — стандартный путь; (вариант проще на старте: initrd-образ, загруженный загрузчиком в RAM).
- **VFS** — виртуальная ФС: единый интерфейс open/read/write/readdir.
- **FAT32** (чтение+запись) поверх VFS. NTFS — только чтение, намного позже.

**DoD:** ядро монтирует диск, `cat /readme.txt` в нашей консоли читает файл с реального образа.

## M7. Пользовательский режим
_4–8 недель_

- Ring 3: TSS, переключение в user mode.
- Syscall-интерфейс: инструкция `syscall/sysret` (не int 0x80 — быстрее).
- Загрузчик **ELF**-программ AresOS, мини-libc, shell.
- Изоляция адресных пространств процессов (каждому — свои таблицы страниц).

**DoD:** shell запускает `hello.elf` как отдельный процесс; краш процесса не роняет ядро.

## M8. Подсистема PE / WinAPI — «Долгая дорога»
_Постоянный этап, начинается когда стабилен M7_

1. **PE loader** (по Microsoft PE/COFF Specification):
   парсинг заголовков DOS/NT, маппинг секций (.text, .data, .rdata) по виртуальным
   адресам, ImageBase, **релокации** (.reloc), таблица импортов (IAT).
2. **kernel32/ntdll-совместимость** — наша реализация:
   - минимум для консольного hello.exe (MinGW): `GetStdHandle`, `WriteConsoleA`,
     `ExitProcess`, `VirtualAlloc/VirtualFree`, `HeapAlloc`, `GetLastError`...;
   - TEB/PEB-структуры, SEH позже.
3. Тестовый стенд: `x86_64-w64-mingw32-gcc hello.c -o hello.exe` → AresOS его запускает.
4. Расширение API-сета → файлы, потоки (CreateThread), DLL → user32/gdi32-стыбы →
   собственная графическая подсистема.

**DoD этапа 1–3:** `hello.exe`, собранный под Windows x64, печатает текст в консоли AresOS.

нельзя** — изучаем идеи и пишем своё по документации Microsoft Learn и PE/COFF spec.
