# AresOS — Архитектура ядра

## Карта виртуальной памяти (x86-64, 4-уровневый paging)

```
0xFFFFFFFFFFFFFFFF ┐
                   │  Higher half
0xFFFFFFFF80000000 ├─ KERNEL (код/данные ядра, -mcmodel=kernel)
                   │
0xFFFF800000000000 ├─ HHDM: прямой маппинг ВСЕЙ физпамяти (2 МиБ страницы)
                   │
0x0000800000000000 ┐
   (canonical gap — не используется)
0x00007FFFFFFFFFFF ┐
                   │  User space (процессы, включая PE-приложения)
0x0000000000400000 ├─ типичный ImageBase для .exe (0x400000)
0x0000000000000000 └─ NULL (страница намеренно не замаплена → ловим баги)
```

Почему так:
- **Higher-half ядро** — стандарт индустрии: user space не пересекается с ядром.
- **HHDM огромными 2-МиБ страницами** — в 512 раз меньше промахов TLB при доступе
  к физпамяти, чем при 4-КиБ страницах. Главная «бесплатная» оптимизация.
- Каждый процесс — собственная таблица страниц (изоляция, требование для PE-загрузчика).

## Подсистемы ядра и зависимости между ними

```
        ┌────────────────────────────────────┐
        │  winsvc: PE-loader + kernel32/ntdll │  (M8)
        ├───────────────┬────────────────────┤
        │  VFS + FAT32  │  Scheduler/Threads │  (M6, M5)
        ├───────────────┴────────────────────┤
        │  PMM · VMM/Paging · kmalloc (Heap) │  (M3)
        ├────────────────────────────────────┤
        │  IDT/Exceptions · APIC · Timer · KBD│  (M2, M4)
        ├────────────────────────────────────┤
        │  Serial log · FB console · kprintf │  (M2)
        ├────────────────────────────────────┤
        │  BOOTX64.EFI (UEFI loader) → ELF   │  (M1)
        └────────────────────────────────────┘
```

Правило: подсистема может вызывать только слои НИЖЕ себя. Никаких
«драйвер диска дёргает планировщик напрямую».

## Структура репозитория

```
AresOS/
├── boot/          # UEFI-загрузчик (BOOTX64.EFI)
├── kernel/        # ядро: arch/x86_64 (asm), mm/, sched/, drivers/, fs/
├── libc/          # крошечная freestanding libc (string/memset/printf)
├── winsvc/        # (M8) PE-loader + реализация kernel32/ntdll
├── tools/         # скрипты сборки образа, генерация шрифтов
├── docs/          # этот файл, ROADMAP, SETUP
├── Makefile       # единая точка сборки: make / make run / make debug
└── linker.ld      # скрипт линковки ядра (higher half)
```

## Ключевые ABI-решения (фиксируем заранее)

- Системный вызов: `syscall/sysret`, номер в `RAX`, аргументы `RDI,RSI,RDX,R10,R8,R9`
  (соглашение System V AMD64, но RCX/R11 заняты CPU — аргумент 4 идёт в R10).
- Ядро компилируется: `-ffreestanding -fno-stack-protector -mno-red-zone -mcmodel=kernel -fno-pic`.
- FPU/SSE в ядре запрещены на старте (`-mno-sse`); включаем позже через FXSAVE
  в переключателе контекста. В userspace SSE разрешён всегда (требование ABI x86-64!).
- Кодировка консоли — UTF-8 снаружи, кодпоинты внутри.

## Философия оптимизации

1. **Не оптимизируем вслепую.** Сначала корректно — потом `rdtsc`-замеры — потом ускорение.
2. Бесплатные победы с первого дня: 2-МиБ страницы для HHDM, `-O2`, `--gc-sections`,
   stripped-бинарник ядра (меньше = быстрее грузится).
3. Загрузчик влияет только на время ЗАГРУЗКИ (наш свой UEFI-loader = нет меню
   и таймаутов → старт за доли секунды). Скорость ЯДРА определяется его кодом:
   x2APIC вместо PIC, LAPIC-timer вместо PIT, spinlock+pause, per-CPU переменные,
   минимум переключений CR3, PCID — на этапах M4+.
